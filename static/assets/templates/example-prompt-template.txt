## 3. Instance vs Class Decision Rules

<!-- WHY: This is the hardest modelling judgment. These five rules act as a sequential
     filter the LLM should apply IN ORDER for every candidate entity. -->

For every entity you extract, apply these tests **in order** — stop at the first decisive answer:

| #   | Test                                                              | If YES →                  | If NO →               |
| --- | ----------------------------------------------------------------- | ------------------------- | ---------------------- |
| 1   | **Can there be multiple distinct instances of this thing?**       | **Class**                 | **Instance**           |
| 2   | **Can this thing be created, destroyed, or change over time?**    | **Instance**              | Continue to next test  |
| 3   | **Do I need OWL rules/restrictions to apply to this category?**   | **Class or Subclass**     | Continue to next test  |
| 4   | **Do members have varying constraints or properties?**            | **Class or Subclass**     | Continue to next test  |
| 5   | **Is there a known, relatively stable list of these?**            | **Instances of a class**  | Default to **Class**   |

## 6. Output Format Requirements

<!-- WHY: Ensures the output is machine-parseable OWL, not just a description. -->

- Output **valid OWL 2.0 in RDF/XML serialisation**
- Use namespace: `http://example.org/fcdo-travel-advice#`
- Import `http://www.w3.org/2002/07/owl#` and `http://www.w3.org/2001/XMLSchema#`
- Every class, property, and instance must have an `rdfs:label` and `rdfs:comment`
- Use `rdfs:comment` to capture the **source text** or paraphrase from the FCDO page
  for traceability
- Include `owl:versionInfo` with the page's "Still current at" date
- Validate: no orphan classes, no undefined property references, all domains/ranges declared
